GitHub Copilot を agent mode にすると、コードベースを調べ、変更を提案し、ファイルを編集して、コマンドを実行します。作業は自分のマシン上でリアルタイムに進むため、VS Code の Copilot Chat では、ツール呼び出しやファイル編集を確認できます。差分をインラインでレビューし、個々の変更を承認または取り消し、エディターを離れずに追加のプロンプトを送って作業を調整、拡張できます。

この演習では、次の内容を学びます。

- アクセシビリティ エージェントの作業をリアルタイムで確認する。
- 提案されたファイル編集をレビューして承認する。
- セッションの途中でエージェントに指示し、高コントラストに加えてライト モードの切り替えを追加する。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ カスタム エージェントが、高コントラスト モードを実装しています。作業中にデザイン チームから追加の要望が届きました。既定のテーマが暗すぎると感じるユーザー向けに、ライト モードも切り替えられるようにします。新しい会話を最初から始めず、既存のセッションに指示を追加して作業を拡張します。

## Copilot の進行状況を確認する

Copilot Chat ビューには、エージェントが調査したファイル、実行したコマンド、提案した編集などの手順が表示されます。各ファイル編集は差分と **Keep** / **Undo** コントロールとともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. 作業中にチャットをスクロールし、ツール呼び出しを確認します。ファイルの読み取りや編集、実行を求められるターミナル コマンドが表示されます。
3. エージェントがファイル編集を提案すると、差分がチャット内に表示されます。
   - **Keep** を選択すると変更を承認します。
   - **Undo** を選択すると変更を取り消し、エージェントに再試行させます。
4. チャット上部の **Files changed** を開くと、このセッションでエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ターミナル コマンドの実行など、ツール呼び出しに権限が必要な場合、エージェントは一時停止して **Allow** の確認を表示します。内容を確認し、許可できるコマンドだけを承認してください。

5. エージェントが高コントラスト モードの実装を完了するまで待ちます。変更をまとめた最後のメッセージが表示されます。

## ライト モードを追加するようエージェントに指示する

高コントラスト モードができたので、同じ会話を続けてライト モードの切り替えを追加します。会話を継続すると、エージェントは変更したコンポーネント、スタイルの方法、設定した local storage のパターンなど、これまでのコンテキストを保持します。

1. Copilot Chat の入力欄に、次のフォローアップ プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは以前の変更を調べ、ライト モードの追加を提案します。
3. 高コントラストのときと同様に、新しい編集を確認し、各差分で **Keep** または **Undo** を選択します。
4. たとえば、切り替え UI のリファクタリングなど、エージェントの方向性が望みと異なる場合は、チャット入力欄の横にある **Stop** ボタンで停止し、説明を補足するプロンプトを送信します。

> [!TIP]
> 進行中のセッションに指示を出すほうが、最初からやり直すより早くなります。「CSS を簡潔にし、セレクターを重複させずに CSS 変数を使う」などの調整、「3 つ目の切り替えを追加せず、既存の設定パネルにライト モードを組み込む」などの軌道修正、「両方の切り替えにキーボード ショートカットも追加する」などの範囲拡張を依頼できます。

## 作業内容をレビューする

変更をコミットする前に、エージェントが編集した内容を確認します。

1. VS Code の **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストが更新されているはずです。
3. いくつかの変更ファイルを開き、差分を確認します。ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定の保持など、カスタム エージェントのアクセシビリティ パターンが反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次の[レッスン][next-lesson]で公開します。

## まとめと次のステップ

Copilot Chat の agent mode でセッションの進行状況を確認し、各ファイル編集をレビューして承認または取り消し、追加プロンプトを使ってコンテキストを保ったまま作業を拡張しました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムで監視した。
- 個々のファイル編集を承認または取り消した。
- フォローアップ プロンプトで進行中のセッションに指示を出した。

次の[レッスン][next-lesson]では、アクセシビリティ機能をプルリクエストとして公開し、このラボでローカルのカスタム エージェントが作成した変更をレビューします。
